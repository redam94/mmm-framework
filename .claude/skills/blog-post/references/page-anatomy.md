# Page anatomy

The structure every one of the 42 posts shares. Copy `assets/post-skeleton.html`, or an
existing post. Never `docs/TEMPLATE-SIDEBAR.html`, which enables single-`$` math.

## Document order

```
<!DOCTYPE html> / <html lang="en">
<head>                              hand-written meta, then asset blocks
  <!-- seo:augmented ... -->        GENERATED by build_seo.py, never hand-write
</head>
<body>
  <!-- Navigation injected by components.js -->
  <div class="page-layout">
    <aside class="sidebar">         hand-maintained TOC
    <main class="main-content">     the post
  </div>
  <!-- Footer injected by components.js -->
  <script src="shared/components.js">
  <!-- Research figures -->         optional IIFE
  <script>                          KaTeX init, always last
</body></html>
```

There is no `<header>`, `<nav>` or `<footer>` in the source. Writing one gives the page two.

## The `<head>`

Hand-written, in this order. Change only the strings.

```html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>POST TITLE | MMM Framework</title>
<link rel="icon" type="image/svg+xml" href="assets/favicon.svg">

<meta name="description" content="Search copy.">
<meta name="author" content="Matthew Reda">
<link rel="canonical" href="https://redam94.github.io/mmm-framework/blog-SLUG.html">
<meta property="og:title" content="POST TITLE">
<meta property="og:description" content="Social copy.">
<meta property="og:url" content="https://redam94.github.io/mmm-framework/blog-SLUG.html">
<meta property="og:image" content="https://redam94.github.io/mmm-framework/assets/mmm-framework-social-preview.png">
<meta property="og:type" content="article">
<meta property="og:site_name" content="MMM Framework">
<meta property="og:locale" content="en_US">
<!-- Twitter Card + JSON-LD structured data are injected by tools/build_seo.py -->
```

`og:type` must be `article`. `build_seo.py` only adds `og:*` when the head has none
(`has_og = head.count('property="og:') > 0`), so it will not correct a wrong value.

Then four asset blocks with their comments, verbatim from any existing post: Fonts,
KaTeX (three CDN tags, all `defer`), Plotly + `shared/blogviz.js` (**not** deferred —
the figure IIFE calls `BV.register` at parse time), Shared Styles.

Per-post `<style>` goes after `shared/styles.css` and before the seo sentinel. Only for
hand-drawn SVG. Namespace every rule under a post-local class and use design tokens
(`var(--color-surface)`, `var(--color-border)`) so dark mode works; hard-coded hex
renders dark-on-dark under the theme toggle.

Everything from `<!-- seo:augmented (structured data + social cards) -->` to `</head>`
is generated. Write the post without it and run the builder.

## Sidebar TOC

Two `<h3>` + `<ul class="sidebar-nav">` pairs. First lists every `<h2>` id in document
order, starting `#overview` (the h1) and ending `#references`. Second is the back-link.

```html
<aside class="sidebar">
    <h3>This Post</h3>
    <ul class="sidebar-nav">
        <li><a href="#overview">Overview</a></li>
        <li><a href="#sample-act-repeat">Sample, Act, Repeat</a></li>
        <li><a href="#references">References</a></li>
    </ul>

    <h3>Research</h3>
    <ul class="sidebar-nav">
        <li><a href="blog.html">&larr; All research posts</a></li>
    </ul>
</aside>
```

TOC labels may be **shorter** than the heading they point at, and are on 28 headings
across 9 pages. That is fine and deliberate. What matters is that the anchor resolves
and that a heading rewrite gets the same edit here when the label would otherwise go
stale. Never change an `id`; other posts deep-link to it.

## Opening: h1, byline, lead

Exactly three elements, no wrapper. All 42 posts use `id="overview"`, `.post-meta`, `.lead`.

```html
<main class="main-content">
    <h1 id="overview">The Optimizer's Curse</h1>
    <p class="post-meta">
        <span>Matthew Reda</span><span aria-hidden="true">&middot;</span>
        <time datetime="2026-07-26">July 26, 2026</time><span aria-hidden="true">&middot;</span>
        <span class="post-tag">MMM</span>
    </p>
    <p class="lead">A budget optimizer built on a fitted MMM does something more specific...</p>
```

The `<time datetime>` is scraped for `datePublished`. Tags in use: Causal inference (12),
MMM (11), Practice (5), Experiments (5), Experimental design (4), Measurement (3),
Bayesian workflow (2).

## Headings and ids

`<h1 id="overview">` once. Sections are `<h2 id="kebab-slug">`; no post has an id-less
`<h2>`. Subsections `<h3 id="slug">`. `<h4>` is reserved for callout titles. The last
section is always `<h2 id="references">References</h2>`.

Ids are short slugs of the *idea*, not of the heading text: `#argmax`, `#not-a-fix`,
`#no-error-bar`, `#limits`, `#fix`, `#next`.

## Callout boxes

Four exist in `shared/styles.css` and are used in posts. **`.key-insight` and `.aside`
do not exist** — neither in the stylesheet nor in any post.

**`.note`** (green, 56 uses) — the general-purpose box: file:line pointers, a small
table, a code snippet.

```html
<div class="note">
    <h4>Where this lives in the code</h4>
    <p><code>BudgetOptimizationResult.shadow_price</code> (<code>planning/budget.py:419-431</code>) sits beside...</p>
</div>
```

**`.definition`** (blue, 53) — the post's one formal object: a named definition, a
theorem, a short derivation. Display math sits as a bare `$$…$$` text node between
paragraphs, not inside a `<p>`.

**`.warning`** (red, 49) — a concrete failure mode, not general caution. One or two per
post. Title usually opens with ⚠️.

**`.takeaway-box`** (41 of 42 posts, at most one each) — the last element before
References, `<h4>Takeaways</h4>` and a `<ul>` of 4-6 dense bullets, each a complete
claim. The guide bans a closing paragraph that restates the piece in miniature; a
takeaway list is not that, because each bullet is a claim the reader can act on. If
yours reads as a summary rather than a set of claims, cut it, as
`blog-prior-was-doing-more.html` does.

**`details.deep-dive`** (29 posts) — optional formalism the main argument does not need.

```html
<details class="deep-dive">
    <summary><span class="deep-dive-tag">Deep dive</span>The entropy-budget argument in four lines</summary>
    <div class="deep-dive-body">
        <p>Write \( I_t = I\big(x^*; (x_t, y_t) \mid \mathbb{H}_{t-1}\big) \)...</p>
    </div>
</details>
```

`.interactive-box` (79) is the figure container; see `figures.md`.

## Math

Inline `\( … \)`. Display: a bare `$$ … $$` text node between block elements. **Single
`$` is not a delimiter**, deliberately, so dollar amounts render as money.

Inside math use `\lt` `\gt` `\le` `\ge`, never a bare `<`, which breaks the HTML.

The init script is the last thing in `<body>`, after `components.js` and after any
figure IIFE, because KaTeX is loaded `defer`.

## Code blocks

`<pre><code>` for illustrative pseudo-code, `<pre><code class="language-python">` for
real API calls. `tests/test_docs_snippets.py` extracts blocks whose `<code>` has class
`python`/`language-python` **or no class at all**, plus every `<div class="code-example">`.
For each it resolves `from mmm_framework… import X` and checks method calls on
conventional names (`model`/`mmm` → BayesianMMM, `results` → MMMResults, `panel` →
PanelDataset, and others) against the real class.

Blog code is illustrative, so **start every Python-ish block with `# illustrative`**.
Alternatives: a first line of `# pseudocode`, or `<!-- doc-snippet: skip -->`.

Escape bare `<` as `&lt;` inside code blocks; a raw one breaks the page.

## Tables

Plain `<table><thead>…<tbody>` as a direct child of `<main>`. `.data-table` appears once
inside a callout but is not defined in the stylesheet, so it is decorative only.

## References

Last section. `<h2 id="references">References</h2>` then a `<ul>` in citation order,
title in `<em>`. 41 of 42 posts use the bare `<ul>`:

```html
<li>Smith, J. E., &amp; Winkler, R. L. (2006). <em>The Optimizer's Curse: Skepticism and
Postdecision Surprise in Decision Analysis</em>. Management Science, 52(3), 311&ndash;322.</li>
```

One post uses `<ul class="reference-list">` with a `<span class="ref-note">` gloss per entry.

Page ranges and author pairs take en dashes (`&ndash;`), which are correct and stay.
Em dashes are banned everywhere, including as a separator inside a reference entry.

## Entities

Posts use named entities rather than raw Unicode: `&ndash;` ranges, `&middot;` byline
separators, `&larr;` back-link, `&hellip;` readout placeholders, `&amp;` in author
lists, `&ldquo;/&rdquo;`, `&rsquo;`, `&approx;`, `&sigma;`, `&nbsp;` binding units to
numbers.

Exception: strings inside Plotly config render entities literally. See `figures.md`.

## After `</main>`

```html
    </main>
    </div>

    <!-- Footer injected by components.js -->

    <!-- Shared Components -->
    <script src="shared/components.js"></script>

    <!-- Research figures -->
    <script>(function () { 'use strict'; ... })();</script>

    <!-- Initialize KaTeX after DOM is ready -->
    <script>...</script>
</body></html>
```

## Injected at runtime

`components.js::init()` inserts the skip link, the site nav with Cmd-K search and theme
toggle, the footer, and the Previous/Next series cards. It also sets `id="main-content"`
on your `<main>`, adds the `.page-meta-chips` row (audience tier + computed reading time)
after the `<h1>`, wraps every `<pre>` with a copy button, auto-links up to 10 glossary
terms in the first 80 paragraphs, and runs the sidebar scrollspy.

Do not hand-write any of it. The chips depend on registration; see `registration.md`.
